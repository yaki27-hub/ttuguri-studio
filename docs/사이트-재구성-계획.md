# 뚜구리 스튜디오 — 사이트 재구성 계획

- 대상: https://ttuguri-studio.vercel.app (저장소 `yaki27-hub/ttuguri-studio`)
- 작성일: 2026-11-15
- 상태: 계획 단계. 아직 코드는 바꾸지 않았음. **데이터 저장 위치 결정이 필요함** (6장).
- 참고 시안: 피그마 Make 「인스타툰·릴스 제작 플랫폼」(`figma.com/make/dQOBTTARY6iyZ7L1WWPLuo`). 검토 결과는 10장.

---

## 1. 이 사이트가 하는 일

뚜구리툰(인스타툰) 1인 작가의 제작 도구입니다.

1. 일상 메모를 받는다.
2. 메모를 콘티로 바꾼다. 형식은 한컷 밈 / 4컷 / 컷자막형 2~4장이며, AI 초안을 받거나 프롬프트를 복사해 붙여넣는다.
3. 콘티를 피그마로 옮겨 그린다. 장면 설명과 화면 문구를 따로 복사한다.
4. 이미지를 붙이고 게시 패키지를 만든다. 패키지는 이미지, 캡션, 대체 텍스트, 콘티 문서를 담은 ZIP이다.
5. 인스타에 올린 뒤 성과를 본다.

- **기술:** Next.js 16 (App Router), React 19, Vercel 배포, 비밀번호 로그인.
- **외부 연결:** 노션(🎬 에피소드 DB), 인스타그램 Graph API, Gemini/Claude.

## 2. 지금 구성

상단 탭은 4개입니다.

| 탭 | 경로 | 하는 일 | 데이터 |
|---|---|---|---|
| 제작 | `/studio`, `/studio/recommend`, `/studio/ep/[id]` | 메모 저장 → 소재 추천 → 에피소드 페이지에서 콘티 생성·단계 넘기기 | 노션 |
| 작업실 | `/studio/work`, `/studio/work/[id]` | 메모 → 콘티 → 이미지 → 게시 4단계, 컷별 편집·잠금·버전, ZIP | 브라우저(IndexedDB)에만 |
| 성과 (첫 화면) | `/` | 게시물 지표, 노션 에피소드 연결, 매일 9시 자동 동기화 | 인스타 → 노션 |
| 설정 | `/studio/settings` | 캐릭터·말투·금지사항·그림체, AI 지시문 미리보기, 백업 | 브라우저 + 기본값 |

단계 이름이 두 벌입니다.

- **노션 제작 상태:** 아이디어 / 스토리 / 콘티 / 이미지 제작 / 검수 / 제작 완료 / 업로드 완료
- **작업실 단계:** 메모 / 콘티 / 이미지 / 게시. 코드에는 옛 `story` 단계가 호환용으로 남아 있습니다.

## 3. 문제

1. **콘티를 만드는 곳이 둘이다.**
   - 제작 탭과 작업실이 같은 일을 따로 한다.
   - 한 에피소드가 노션과 브라우저에 나뉘어 저장된다.
2. **작업실 내용이 다른 기기로 이어지지 않는다.**
   - 맥에서 만든 콘티가 폰에서 안 보인다.
   - 브라우저 데이터가 지워지면 백업 ZIP이 없는 한 같이 사라진다.
   - 메모는 폰으로 하는데, 메모를 받는 쪽은 노션이다.
3. **단계 이름이 맞지 않는다.** 노션 상태 7개와 작업실 단계 4개를 사람이 머릿속으로 맞춰야 한다.
4. **첫 화면이 성과다.** 매일 하는 일은 작업인데 지표가 먼저 뜬다.
5. **설정이 브라우저에만 있다.** 기기를 바꾸면 캐릭터 설정을 다시 넣어야 한다.

## 4. 바꾼 뒤 구성 (탭 3개)

```
[작업]  ← 첫 화면
  ├ 입력칸 하나 (폰에서 바로) — 글은 소재 메모, 링크는 레퍼런스로 자동 구분
  ├ 메모함 (아직 콘티 안 만든 메모) ─ [소재 추천] 버튼
  ├ 레퍼런스 보드 (다른 계정 게시물 모음, 검색·형식·태그 필터)
  └ 진행 중 에피소드 목록 (단계 배지, 인스타툰/카드뉴스 표시)
        └ 에피소드 화면: 메모 → 콘티 → 이미지 → 게시
           왼쪽: 원문 메모 + 연결된 레퍼런스 / 가운데: 작업 칸 / 오른쪽: 게시 미리보기
[성과]  게시물 지표, 에피소드에 자동 연결
[설정]  캐릭터·그림체·AI 지시문·연결 상태·백업
```

- 제작 탭과 `/studio/ep/[id]`는 없애고, 에피소드 화면은 지금 작업실 화면 하나만 쓴다.
- 소재 추천(`/studio/recommend`)은 메모함 안의 버튼으로 옮긴다.
- 단계는 한 벌로 통일한다.

| 통일 단계 | 노션 제작 상태 |
|---|---|
| 메모 | 아이디어 |
| 콘티 | 콘티 |
| 이미지 | 이미지 제작 |
| 게시 준비 | 제작 완료 |
| 게시됨 | 업로드 완료 |

  "스토리"와 "검수"는 쓰지 않는다. 노션의 옛 값은 그대로 두되, 읽을 때 가까운 단계로 바꿔 보여준다.
- 성과 화면은 게시물을 에피소드에 연결하면 그 에피소드의 '게시됨' 카드에 지표가 함께 보이게 한다.

- 에피소드에 **콘텐츠 유형**을 둔다. 값은 인스타툰과 카드뉴스다.
  - 카드뉴스는 4:5(1080×1350)를 기본으로 한다.
  - 카드뉴스는 컷자막형 흐름을 그대로 쓰되, 장 수를 늘릴 수 있게 한다(최대 10장).

### 새로 넣는 것: 레퍼런스 보드

참고할 다른 계정 게시물을 모아 두고, 에피소드에 연결해 콘티를 쓸 때 옆에 띄워 본다.

| 항목 | 내용 |
|---|---|
| 원본 링크 | 필수, 중복 저장 막기(쿼리·# 제거 후 비교) |
| 플랫폼 | 링크로 자동 판별: Instagram / YouTube / 기타 |
| 계정명 | 필수, 앞의 @ 자동 제거 |
| 게시물 유형 | 피드 / 릴스 / 캐러셀 |
| 형식 | 한컷 / 3컷 / 4컷 / 캐러셀 / 기타 |
| 태그 | 회사생활 / 일상 / 개인 프로젝트 (설정에서 추가 가능하게) |
| 좋아요·댓글·조회수 | "3.4천", "15만"처럼 적어도 숫자로 저장. 지표 입력일·출처(직접 확인 / 추정치) 함께 기록 |
| 뚜구리 버전 | 이 소재를 뚜구리 개그로 바꾼 한 줄 (100자 이내) |
| 참고 메모 | 연출·후킹·컷 구성에서 참고할 점 |
| 썸네일·캡션·원본 게시일 | 선택 |

- 레퍼런스에서 바로 [이 소재로 에피소드 만들기]를 누를 수 있게 하고, 누르면 레퍼런스가 연결된 채로 에피소드가 생긴다.
- 소재 추천 AI는 내 메모, 내 성과, 레퍼런스(특히 '뚜구리 버전')를 함께 재료로 쓴다.
- 레퍼런스 원본 이미지·캡션은 참고용으로만 쓰고, 콘티 프롬프트에 그대로 베끼지 않게 한다.

### 바꾸지 않는 것

- 작업실의 콘티 기능 전부: 형식 자동 추천, 📌 대사 고정, 장면 설명·화면 문구 분리 복사, 컷 잠금·버전, 걸린 시간 표시.
- AI 초안 방식 두 가지: 서버 키로 받기, 또는 프롬프트 복사 → 붙여넣기.
- 게시 패키지 ZIP 형식.
- 콘티 프롬프트 키트(`docs/konti-kit/`).

## 5. 화면별 할 일

### 작업 (첫 화면, `/studio`)

- 입력칸을 맨 위에 둔다.
  - 글을 쓰면 메모 단계 에피소드가 바로 생긴다.
  - 링크를 붙이면 레퍼런스 입력칸(계정·형식·태그·지표·뚜구리 버전)이 펼쳐진다.
- 레퍼런스 보드는 카드 목록으로 보여준다. 검색(계정·메모), 형식·태그 필터, 정렬(최근·좋아요·조회수)이 있다.
- 메모함 카드: 메모 첫 줄, 날짜, [콘티 뽑기] 버튼이 있다. 버튼을 누르면 에피소드 화면의 콘티 단계로 간다.
- 진행 중 목록은 단계별로 묶는다. 게시됨은 접어 둔다.
- 폰 화면을 기준으로 만든다.

### 에피소드 (`/studio/work/[id]`)

- 지금 화면의 기능은 모두 유지한다.
- 넓은 화면에서는 3단으로 배치한다.
  - **왼쪽:** 원문 메모와 연결된 레퍼런스. [+ 추가]로 보드에서 고르고, ×로 연결을 푼다.
  - **가운데:** 단계별 작업 칸.
  - **오른쪽:** 게시 미리보기와 레퍼런스 보기 탭.
- 폰에서는 가운데 칸만 보이고, 왼쪽과 오른쪽은 접힌 패널로 연다.
- 저장 위치는 6장의 결정에 따라 바꾼다.

### 성과 (`/stats`로 이동)

- 지금 `/` 화면을 옮긴다. `/`는 작업 화면으로 보낸다.

### 설정

- 설정을 서버에 저장해 기기 간 공유한다.
- 백업 ZIP 기능은 유지한다.

## 6. 결정 필요: 데이터를 어디에 둘지

### A안 — 노션을 원본으로

- 에피소드, 콘티 컷, 버전을 모두 노션에 저장한다. 컷은 하위 DB나 본문 블록에 둔다.
- 이미지는 노션 파일 첨부로 올린다.
- **장점:** 새 서비스가 없다. 노션에서 바로 보고 고칠 수 있다.
- **단점:**
  - 컷별 버전·잠금처럼 잦은 저장은 노션 API 속도 제한(초당 약 3회)에 걸리기 쉽다.
  - 이미지 업로드가 번거롭다.
  - 구조가 노션 화면에 맞춰 제한된다.

### B안 — 서버 DB를 새로 (추천)

- Vercel Marketplace에서 DB 하나(예: Neon Postgres 또는 Supabase)를 연결하고, 이미지는 Vercel Blob에 둔다.
- 작업 데이터 원본은 DB에 둔다. 노션에는 제목, 상태, 형식, 게시 링크, 성과만 기록한다(지금 성과 동기화와 같은 방식).
- **장점:**
  - 지금 작업실 데이터 구조(`lib/work/types.ts`)를 거의 그대로 옮길 수 있다.
  - 빠르고, 기기 간에 바로 이어진다.
- **단점:**
  - 처음 연결 설정이 한 번 필요하다.
  - 무료 한도 안에서 쓸 예정이다.

### C안 — 지금처럼 브라우저 + 노션 기록

- 가장 적게 바꾸는 안이다. 하지만 3장의 2번 문제(기기 간 안 이어짐)가 그대로 남는다.

**추천: B안.** 작업실 기능이 이미 많이 쌓였고, 폰과 맥을 오가는 게 핵심 불편이기 때문이다.

## 7. 옮기는 순서

1. **저장소 정리**
   - 작업실의 저장 코드(`lib/work/db.ts`, `repo.ts`)를 바꿔 끼울 수 있게 한 겹 감싼다.
   - 화면 코드는 그대로 둔다.
2. **새 저장소 연결**
   - 6장에서 고른 저장소를 붙인다.
   - 설정과 에피소드가 서버에 저장되는지 확인한다.
3. **기존 데이터 이전**
   - 설정 화면에 "브라우저 데이터 서버로 올리기" 버튼을 둔다(한 번만).
   - 백업 ZIP 가져오기도 서버로 저장되게 한다.
4. **노션 에피소드 가져오기**
   - 노션의 아이디어·스토리·콘티 상태 페이지를 메모함 / 에피소드로 불러온다.
   - 노션 원본은 지우지 않는다.
5. **화면 재구성**
   - 첫 화면을 작업 화면으로 바꾼다. 입력칸 하나에서 메모와 링크를 자동으로 구분한다.
   - 레퍼런스 보드와 에피소드 연결을 추가하고, 콘텐츠 유형(인스타툰/카드뉴스)을 추가한다.
   - 에피소드 화면을 3단으로 배치하고, 디자인 톤을 10장대로 맞춘다.
   - 제작 탭과 `/studio/ep/[id]`를 정리하고, 소재 추천 버튼을 옮긴다.
   - 성과는 `/stats`로 옮긴다.
6. **단계 통일:** 노션 상태 동기화 규칙을 4장 표대로 맞춘다.
7. **확인**
   - 폰에서 메모 → 맥에서 콘티 → 폰에서 확인하는 흐름을 실제 사이트에서 끝까지 해본다.

각 단계는 따로 배포할 수 있게 나눈다. 5번 전까지는 지금 화면이 그대로 동작해야 한다.

## 8. 완료 기준

- 폰에서 쓴 메모가 맥 작업 화면에 바로 보인다.
- 콘티를 만드는 화면이 하나뿐이다.
- 단계 이름이 사이트와 노션에서 같다.
- 기존 작업실 데이터와 노션 진행 중 에피소드가 빠짐없이 옮겨졌다.
- 첫 화면에서 메모 입력까지 탭 0번이다.
- 인스타 링크를 붙이면 레퍼런스로 저장되고, 같은 링크는 두 번 저장되지 않는다.
- 에피소드 콘티 화면에서 연결한 레퍼런스를 옆에 띄워 볼 수 있다.
- 로그인하지 않은 사람은 어떤 데이터도 읽거나 고칠 수 없다.

## 10. 피그마 Make 시안 검토 (2026-11-15)

시안 코드를 내려받아 읽었다(실행은 하지 않음).

- **구성:** Next.js 16 + Payload CMS 4.0 베타 + Tailwind.
- **저장 항목:** 에피소드, 레퍼런스, 미디어, 폴더, 태그, 관리자.

### 가져올 것

- 입력칸 하나로 메모/링크 자동 구분
- 레퍼런스 보드 (항목은 4장 표). 지표의 "천·만" 표기를 숫자로 바꾸는 규칙 포함
- 에피소드 ↔ 레퍼런스 연결, 레퍼런스에서 바로 에피소드 만들기
- 콘텐츠 유형: 인스타툰 / 카드뉴스
- 에피소드 화면 3단 배치 (메모·레퍼런스 / 작업 / 미리보기)
- **디자인 톤**
  - 따뜻한 회백색 배경(#f8f7f5)과 보라 포인트(#7956ce, #6849b1)
  - 둥근 카드(16~24px)와 굵은 제목
  - 넓은 화면에서는 왼쪽 사이드 메뉴를 쓴다
  - 글꼴은 Pretendard

### 가져오지 않을 것 / 그대로 쓰면 안 되는 것

- **로그인 없음:** 모든 데이터가 누구에게나 읽기·쓰기·삭제로 열려 있다. 이대로 공개하면 안 되며, 지금 사이트의 비밀번호 로그인을 유지한다.
- **콘티가 메모 칸 하나뿐:** 지금 작업실의 컷별 편집, 📌 대사 고정, 버전, 장면/문구 분리 복사, AI 초안을 유지한다.
- **동작하지 않는 화면 요소:**
  - 소재 추천은 고정 예시 글 3개다.
  - 내보내기, 이미지 스타일 바꾸기, 이미지 내려받기 버튼은 비어 있다.
  - 사이드 메뉴의 성과·설정은 비어 있다.
- **피그마 Make 전용 설정과 베타 버전 의존:** `@payloadcms/figma`와 Payload 4.0 베타에 의존한다. 그래서 시안 코드를 통째로 옮기지 않고, 지금 저장소에 화면과 규칙만 다시 만든다.
- 인스타 성과·노션·AI 연결은 시안에 없으므로 지금 사이트의 것을 그대로 쓴다.

### 6장 결정과의 관계

시안도 서버 DB에 저장하는 구조라 **B안과 방향이 같다.** B안의 저장 항목에 `레퍼런스`와 `에피소드-레퍼런스 연결`을 더한다. 썸네일 이미지는 Vercel Blob에 둔다.
